# ttd — загрузчик видео и фото из TikTok

`ttd` скачивает видео, фото-слайдшоу, публикации профиля и истории из TikTok
и раскладывает файлы по папкам, в имени которых указаны **дата скачивания** и
**дата публикации**:

```
~/ttd/19.10.2026 | 17.10.2026/user_7412345678901234567.mp4
        └──────┬──────┘ └──────┬──────┘
        дата скачивания   дата публикации
```

Программа написана на Go (один статический бинарник, без внешних
Go-зависимостей), работает на **Linux**, **macOS** и **Windows** и умеет
работать в трёх режимах:

| Режим | Команда | Для чего |
| --- | --- | --- |
| **CLI** | `ttd <ссылка>` | скрипты, автоматизация, быстрые загрузки |
| **TUI** | `ttd tui` | полноэкранный интерфейс в терминале |
| **Web** | `ttd web` | сайт на `localhost`, открывается скриптом |

## Возможности

- **Видео, фото и слайдшоу.** Обычные видео, публикации с несколькими фото и
  «карусели» скачиваются полностью.
- **Профиль целиком.** Укажите ссылку на аккаунт — скачаются все публикации.
- **Истории.** Поддерживаются истории профиля (фото и видео) — ключ `--stories`.
- **Максимальное качество.** Программа сама определяет доступные разрешения и
  выбирает наилучшее (`ttd probe` показывает, что доступно).
- **Папки с двумя датами.** Скачанные сегодня файлы старых публикаций попадают
  в разные папки — видно и когда скачали, и когда это было опубликовано.
- **Пропуск повторов.** Уже скачанное не качается заново (можно отключить).
- **Три интерфейса** — командная строка, TUI и локальный сайт.
- **Движки уже внутри.** gallery-dl, yt-dlp и их Python-зависимости встроены в
  бинарник: установка и `ttd install` не обращаются к интернету. Обновить
  движки можно командой `ttd install --online`, когда интернет есть.
- **Linux, macOS, Windows.** Один и тот же код и одинаковые команды на всех
  трёх платформах; TUI, CLI и сайт работают везде.
- **Один бинарник.** Go-код не тянет внешних Go-модулей; движки и их
  зависимости встроены и ставятся в изолированное окружение из локального
  набора, без скачивания из интернета.

## Платформы

| Платформа | Установка | Командная оболочка |
| --- | --- | --- |
| **Linux** (x86_64, arm64) | `./install.sh` | bash, zsh |
| **macOS** (Intel, Apple Silicon) | `./install.sh` | zsh (по умолчанию), bash |
| **Windows 10/11** (x86_64) | `install.ps1` или `install.sh` в Git Bash | PowerShell, cmd, Git Bash |

`install.sh` сам определяет платформу: на Linux и macOS ставит бинарник и
движки, а на Windows (через Git Bash / MSYS2) — `ttd.exe`. Для cmd и PowerShell
предусмотрен отдельный `install.ps1` (запускается из `install.cmd` или напрямую).

Особенности платформ:

- **Пути.** Linux/macOS: `~/.local/bin`, `~/.local/share/ttd`,
  `~/.config/ttd/config.json`. Windows: `%USERPROFILE%\.local\bin`,
  `%APPDATA%\ttd`.
- **Имена папок.** В Linux/macOS разделитель дат — `|`, в Windows — `-`
  (символ `|` запрещён в именах файлов). Библиотека читается с любым из них.
- **TUI.** На Windows используется виртуальный терминал (Windows Terminal или
  conhost 10+); если консоль не поддерживает VT, TUI переходит в построчный
  режим.

## Быстрый старт

Нужны **Go 1.22+** и **Python 3.10+** (Python нужен только движкам загрузки).
Интернет требуется только для самих видео и для необязательного
`ttd install --online`; установка движков работает офлайн.

### Linux и macOS

```bash
git clone <адрес-репозитория> ttd
cd ttd
./install.sh             # собрать, установить в PATH, поставить движки
ttd doctor               # проверка окружения
ttd "https://www.tiktok.com/@user/video/7412345678901234567"
```

### Windows (PowerShell)

```powershell
git clone <адрес-репозитория> ttd
cd ttd
powershell -ExecutionPolicy Bypass -File .\install.ps1
ttd doctor
ttd "https://www.tiktok.com/@user/video/7412345678901234567"
```

Или двойным щелчком по `install.cmd`, либо из Git Bash тем же `./install.sh`.

Установщик кладёт программу в `~/.local/bin` (Windows:
`%USERPROFILE%\.local\bin`), движки — в `~/.local/share/ttd/venv` (Windows:
`%APPDATA%\ttd\venv`), и добавляет нужный путь в `~/.bashrc` и `~/.zshrc`
(на Windows — в PATH пользователя). После этого `ttd` работает из любого
каталога, а исходники можно удалить.

Запуск сайта на localhost:

```bash
./scripts/serve.sh       # или:  ttd web
```

Подробная пошаговая инструкция — в файле [INSTALL.md](INSTALL.md).

### Что и куда устанавливается

| Что | Linux / macOS | Windows |
| --- | --- | --- |
| Бинарник `ttd` | `~/.local/bin/ttd` | `%USERPROFILE%\.local\bin\ttd.exe` |
| Движки `gallery-dl`, `yt-dlp` | `~/.local/share/ttd/venv` | `%APPDATA%\ttd\venv` |
| Настройки | `~/.config/ttd/config.json` | `%APPDATA%\ttd\config.json` |
| Скачанные файлы | `~/ttd` | `%USERPROFILE%\ttd` |

Изменить каталоги можно флагами `./install.sh --bin-dir … --data-dir …`
(на Windows — `install.ps1 -BinDir … -DataDir …`).

## Движки (офлайн)

`ttd` не разбирает TikTok сам — загрузкой занимаются два внешних движка:
**gallery-dl** и **yt-dlp**. Оба вместе с зависимостями (`requests`,
`urllib3`, `certifi`, `idna`, `charset_normalizer`) поставляются внутри
бинарника:

| Движок | Версия в сборке | Лицензия |
| --- | --- | --- |
| gallery-dl | 1.32.17 | GPL-2.0 |
| yt-dlp | 2026.8.19 | Unlicense |

При первом запуске (или по команде `ttd install`) создаётся изолированное
окружение, и пакеты ставятся в него через `pip --no-index` — **интернет не
используется**. Уже установленное окружение повторно не пересоздаётся.

Обновление, когда интернет есть:

```bash
ttd install --online            # свежие версии с PyPI
```

Офлайн-обновление из заранее скачанных колёс:

```bash
ttd install --wheels ~/ttd-wheels
```

Проверка: `ttd doctor` показывает и версии, встроенные в сборку, и фактически
установленные. Сводка лицензий — в
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md), полные тексты — внутри колёс
в каталоге `internal/installer/wheels`.

Единственное, что нужно установить отдельно, — **Python 3.10+** (и модуль
`venv`, который входит в официальные сборки Python). `ffmpeg` для TikTok не
обязателен: движки скачивают готовые mp4; он нужен только для нестандартных
случаев вроде склейки отдельных дорожек или `--audio-only`.

## Как работает раскладка по датам

Каждый файл кладётся в папку вида:

```
[ДАТА СКАЧИВАНИЯ] | [ДАТА ПУБЛИКАЦИЙ]
```

в формате `ДД.ММ.ГГГГ`, внутри каталога библиотеки (по умолчанию `~/ttd`).

Например, вы сегодня (19.10.2026) скачали три публикации профиля:

```
~/ttd/
├── 19.10.2026 | 19.10.2026/     ← опубликовано и скачано сегодня
│   └── user_7390000000000000001.mp4
├── 19.10.2026 | 17.10.2026/     ← скачано сегодня, опубликовано 17-го
│   └── user_7389000000000000002.mp4
└── 19.10.2026 | 01.10.2025/     ← скачано сегодня, опубликовано год назад
    ├── user_7380000000000000003_01.jpg
    └── user_7380000000000000003_02.jpg
```

> **Windows:** символ `|` в именах файлов запрещён, поэтому там папка
> называется `19.10.2026 - 17.10.2026`. При чтении библиотеки `ttd` понимает
> оба варианта — каталог можно переносить между Linux, macOS и Windows.

Дата публикации берётся из метаданных, которые возвращает движок:

- **gallery-dl** — флаг `--write-metadata` (поле `date`);
- **yt-dlp** — флаг `--write-info-json` (поля `upload_date` / `timestamp`).

Служебные файлы метаданных после раскладки удаляются. Если движок не смог
определить дату публикации, справа подставляется дата скачивания.

Дату скачивания можно задать вручную: `ttd --date 01.01.2027 <ссылка>`.

## Куда сохранять: локально, NAS и облако

У `ttd` два режима сохранения.

**Постоянная библиотека** — обычный режим: папки-даты, пропуск повторов и
просмотр в TUI/на сайте. По умолчанию это `~/ttd`, но её можно перенести на
смонтированный NAS или в папку синхронизации Nextcloud/ownCloud.

**Разовая папка** — файлы просто складываются в указанный каталог без
папок-дат, индекса и архива повторов. Удобно, когда нужно быстро забрать
несколько видео и не пополнять библиотеку.

### Смонтированные NAS и облако

`ttd` работает с любыми смонтированными каталогами: SMB/CIFS, NFS, sshfs,
папкой синхронизации Nextcloud/ownCloud, диском Windows. Пароли и сетевые
протоколы остаются на уровне ОС — в настройках `ttd` хранятся только пути.

Linux (примеры):

```bash
# SMB/CIFS
sudo mount.cifs //nas.local/media /mnt/nas -o username=user,uid=$(id -u)

# NFS
sudo mount -t nfs nas.local:/volume1/media /mnt/nas

# sshfs
sshfs user@server:/srv/ttd ~/mnt/server
```

macOS:

```bash
mkdir -p ~/mnt/nas
mount_smbfs //user@nas.local/media ~/mnt/nas
```

Windows: подключите сетевой диск через проводник или `net use Z: \\nas\media`
и используйте путь `Z:\ttd`.

Nextcloud/ownCloud: включите синхронизацию папки (или смонтируйте WebDAV
через `davfs2`) и укажите локальный путь синхронизированной папки.

### Профили назначения

Чтобы не вводить длинный путь каждый раз, добавьте именованные профили:

```bash
ttd config --add-storage nas=/mnt/nas/ttd
ttd config --add-storage cloud=~/Nextcloud/ttd

# посмотреть настройки и профили
ttd config

# удалить профиль
ttd config --remove-storage nas
```

Профиль можно указать в `--to`. Если каталог профиля не существует (например,
NAS не смонтирован), `ttd` остановится с ошибкой, а не создаст пустую папку на
локальном диске:

```bash
ttd --to nas "https://www.tiktok.com/@user/video/7412345678901234567"
ttd --to /mnt/nas/ttd "https://www.tiktok.com/@user/video/7412345678901234567"
```

При `--to` файлы и служебный архив (`.ttd-cache`) создаются сразу в папке
назначения. Если же выбрать профиль уже после загрузки, архив останется в
исходной библиотеке (см. ниже).

Сделать папку постоянной библиотекой:

```bash
ttd config --set-dir /mnt/nas/ttd
# или разово:
ttd --dir /mnt/nas/ttd "https://www.tiktok.com/@user/video/7412345678901234567"
```

### Разовая папка

```bash
ttd --temp /tmp/ttd-oneoff "https://www.tiktok.com/@user/photo/7412345678901234567"
```

Файлы окажутся прямо в `/tmp/ttd-oneoff` (без `ДАТА | ДАТА`), архив повторов и
`.ttd-cache` не создаются. Настройка нигде не запоминается.

### Выбор после скачивания

Если запустить `ttd` в терминале без `--to`, `--temp` и `--dir`, после
загрузки появится вопрос:

```
Куда сохранить скачанное?
  1) оставить в постоянной библиотеке — /home/user/ttd
  2) nas — /mnt/nas/ttd
  3) разовая папка (без папок-дат, индекса и архива)
  4) сделать постоянной другую папку
  0) ничего не делать
```

Для профиля и разовой папки CLI спросит «переместить или скопировать»
(по умолчанию — переместить); новая постоянная папка сразу переносится и
сохраняется в `media_root`. В TUI для любого варианта доступны `m` и `c`, на
сайте — флажок «оставить копию». При переносе исходная папка-дата удаляется,
если опустела. Архив повторов остаётся в исходной библиотеке: файл считается
уже скачанным, даже если вы его перенесли.

Отключить вопрос: `--no-ask`, `ttd config --no-ask-destination` или переменная
`TTD_ASK_DESTINATION=false`. В TUI и на сайте вопрос показывается автоматически
(его тоже можно отключить этой настройкой).

> `ttd list`, TUI и сайт показывают **постоянную** библиотеку
> (`media_root`). Файлы, перемещённые в профиль или разовую папку, там больше
> не отображаются — это ожидаемо.

## Использование CLI

```bash
# Скачать одно видео
ttd "https://www.tiktok.com/@user/video/7412345678901234567"

# Публикация с фото
ttd "https://www.tiktok.com/@user/photo/7412345678901234567"

# Весь профиль вместе с историями
ttd --stories "https://www.tiktok.com/@user"

# Несколько ссылок сразу
ttd URL1 URL2 URL3

# Посмотреть доступное качество, не скачивая
ttd probe "https://www.tiktok.com/@user/video/7412345678901234567"

# Список библиотеки (с файлами)
ttd list --files

# Результат в JSON (для скриптов)
ttd -j "https://www.tiktok.com/@user/video/7412345678901234567"
```

Основные флаги команды `download`:

| Флаг | Значение |
| --- | --- |
| `-d`, `--dir <путь>` | каталог библиотеки (по умолчанию `~/ttd`) |
| `--to <имя\|путь>` | сохранить в профиль NAS/облака или в папку |
| `--temp <путь>` | разовая папка: без дат, индекса и архива |
| `--ask` / `--no-ask` | спрашивать ли, куда сохранить, после загрузки |
| `-e`, `--engine <движок>` | `auto`, `gallery-dl`, `yt-dlp`, `mock` |
| `-q`, `--quality <качество>` | `best`, `1080`, `720`, `480` |
| `--date <ДД.ММ.ГГГГ>` | дата скачивания для папки |
| `--stories` / `--no-stories` | качать ли истории профиля |
| `-n`, `--limit <число>` | ограничить число записей |
| `--audio-only` | только звук (mp3) |
| `--cookies <файл>` | cookies в формате Netscape |
| `--cookies-from-browser <браузер>` | взять cookies из браузера (`firefox`, `chrome`, …) |
| `--no-archive` | не пропускать уже скачанное |
| `--engine-arg <аргумент>` | дополнительный аргумент движка (можно повторять) |
| `--dry-run`, `--plan` | показать план без скачивания |
| `-j`, `--json` | машинночитаемый результат |
| `-v`, `--verbose` | подробный журнал |
| `-Q`, `--quiet` | без промежуточного вывода |

Остальные команды:

```bash
ttd install     # установить/переустановить движки
ttd doctor      # состояние окружения и версии движков
ttd config      # показать текущие настройки
ttd config --set-dir /mnt/nas/ttd
ttd config --add-storage nas=/mnt/nas/ttd
ttd config --add-storage cloud=~/Nextcloud/ttd
ttd config --remove-storage nas
ttd config --no-ask-destination
ttd version     # версия
ttd help        # справка
```

Коды выхода: `0` — успех, `1` — были ошибки, `2` — неверные аргументы,
`130` — прервано пользователем (Ctrl-C).

## Текстовый интерфейс (TUI)

```bash
ttd tui
```

Управление:

| Клавиша | Действие |
| --- | --- |
| `Enter` | добавить ссылку в очередь |
| `F5` / `Ctrl-D` | начать загрузку |
| `F10` / `Ctrl-Q` | выход |
| `Tab` | включить/выключить истории |
| `Ctrl-L` | очистить очередь |

Экран показывает очередь с состоянием каждой ссылки, прогресс, текущий файл и
журнал событий. Полноэкранный режим работает на Linux, macOS и Windows
(Windows Terminal или conhost с поддержкой VT). Если терминал не поддерживает
такой режим, TUI автоматически переключается на построчный ввод.

После загрузки TUI открывает экран «куда сохранить скачанное»: пункты
1–9 выбирают профиль или действие, `m`/`c` — переместить/скопировать,
`Esc` — оставить как есть. Для разовой папки и новой постоянной папки путь
вводится вручную. Вопрос отключается флагом `--no-ask` или настройкой
`ask_destination` (см. [Настройки](#настройки)).

## Локальный сайт (Web)

```bash
ttd web                       # по умолчанию http://127.0.0.1:8787/
ttd web --port 9000           # другой порт
ttd web --host 0.0.0.0        # слушать все интерфейсы
ttd web --no-browser          # не открывать браузер автоматически

./scripts/serve.sh            # то же самое через скрипт
```

На странице можно:

- вставить список ссылок и скачать их;
- выбрать движок, качество, включить истории и «только звук»;
- видеть прогресс, журнал и кнопку остановки;
- после загрузки выбрать, куда сохранить файлы: оставить в библиотеке,
  переместить/скопировать в профиль NAS/облака, в разовую папку или сделать
  папку постоянной;
- просматривать библиотеку: папки-даты, превью фото и проигрывание видео прямо
  в браузере (сервер поддерживает HTTP `Range`, поэтому перемотка работает).

Веб-API (на случай интеграций):

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/meta` | настройки, пути, версии движков |
| `GET` | `/api/library` | список папок-дат и файлов |
| `GET` | `/api/files?folder=…&name=…` | отдача файла (с поддержкой `Range`) |
| `POST` | `/api/download` | запустить загрузку, вернуть `id` задачи |
| `GET` | `/api/job/<id>?since=N` | состояние задачи и события начиная с `N` |
| `POST` | `/api/job/<id>/cancel` | остановить задачу |

## Поддерживаемые ссылки

| Тип ссылки | Пример | Как обрабатывается |
| --- | --- | --- |
| Видео | `tiktok.com/@user/video/7412…` | yt-dlp (максимальное качество), gallery-dl как запасной |
| Фото / слайдшоу | `tiktok.com/@user/photo/7412…` | gallery-dl (все кадры публикации) |
| Профиль | `tiktok.com/@user` | gallery-dl — все публикации |
| Истории | `tiktok.com/@user/stories` | gallery-dl (нужен флаг `--stories` или ссылка на истории) |
| Подборка | `tiktok.com/collection/…`, `tiktok.com/music/…` | gallery-dl |
| Короткие ссылки | `vm.tiktok.com/…` | разрешаются автоматически |

Движки — это внешние программы, которые `ttd install` ставит в изолированное
окружение `~/.local/share/ttd/venv`:

- **[gallery-dl](https://github.com/mikf/gallery-dl)** — основной движок:
  понимает профили, фото-слайдшоу и **истории**, умеет сортировать видео по
  убыванию разрешения;
- **[yt-dlp](https://github.com/yt-dlp/yt-dlp)** — скачивает одиночные видео с
  явным выбором наилучшего качества и работает как запасной вариант.

Оба вызываются как подпроцессы, поэтому Go-код остаётся без зависимостей.

## Качество загрузки

Для одиночного видео выбирается максимально возможное качество:

```
-f "bestvideo*+bestaudio/best" --merge-output-format mp4
```

Итоговый файл — `mp4` со склеенными дорожками. Формат `bestvideo*` заставляет
yt-dlp брать видео даже в тех случаях, когда оно помечено как «только с
аудио» — так на TikTok получается максимальное разрешение.

Проверить доступные разрешения заранее:

```bash
ttd probe "https://www.tiktok.com/@user/video/7412345678901234567"
```

Ограничить разрешение можно флагом `-q`: `-q 720` даст не выше 720p,
`-q 1080` — не выше 1080p.

## Доступ по cookies

Иногда TikTok отвечает `403` или просит вход. Тогда передайте cookies:

```bash
# взять из браузера (самый простой способ)
ttd --cookies-from-browser firefox "https://www.tiktok.com/@user/video/7412…"

# или указать файл cookies в формате Netscape
ttd --cookies ~/cookies.txt "https://www.tiktok.com/@user/video/7412…"
```

Поддерживаются браузеры, которые понимает движок: `firefox`, `chrome`,
`chromium`, `edge`, `brave`, `opera`, `safari`, `vivaldi`, `whale`.

## Настройки

Файл настроек:
`~/.config/ttd/config.json` на Linux/macOS и `%APPDATA%\ttd\config.json` на
Windows (создаётся при необходимости). Посмотреть действующие значения —
`ttd config`.

| Поле | Переменная окружения | По умолчанию | Описание |
| --- | --- | --- | --- |
| `media_root` | `TTD_DIR` | `~/ttd` | каталог библиотеки |
| `engine` | `TTD_ENGINE` | `auto` | движок по умолчанию |
| `quality` | `TTD_QUALITY` | `best` | качество по умолчанию |
| `include_stories` | `TTD_STORIES` | `false` | качать истории профиля |
| `cookies` | `TTD_COOKIES` | — | путь к файлу cookies |
| `cookies_from_browser` | `TTD_COOKIES_FROM_BROWSER` | — | браузер для cookies |
| `host` | `TTD_HOST` | `127.0.0.1` | адрес веб-сервера |
| `port` | `TTD_PORT` | `8787` | порт веб-сервера |
| `download_limit` | `TTD_LIMIT` | `0` (без лимита) | ограничение числа записей |
| `gallery_dl` | `TTD_GALLERY_DL` | — | путь к gallery-dl |
| `yt_dlp` | `TTD_YT_DLP` | — | путь к yt-dlp |
| `use_archive` | `TTD_ARCHIVE` | `true` | пропускать уже скачанное |
| `ask_destination` | `TTD_ASK_DESTINATION` | `true` | спрашивать, куда сохранить, после загрузки |
| `storages` | — | `{}` | именованные пути NAS/облака: `{"nas": "/mnt/nas/ttd"}` |

Дополнительные переменные (не входят в файл настроек):

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `TTD_HOME` | каталог бинарника | где искать исходники и `.venv` |
| `TTD_DATA_DIR` | `~/.local/share/ttd` / `%APPDATA%\ttd` | каталог данных установленного ttd |
| `TTD_VENV` | — | явный путь к окружению с движками |

Так `ttd` ищет окружение с движками: `TTD_VENV` → `.venv` рядом с исходниками
→ `<каталог данных>/venv` → системные каталоги. Если готового окружения нет,
новое создаётся в `TTD_DATA_DIR` (по умолчанию `~/.local/share/ttd`).

Пример `~/.config/ttd/config.json`:

```json
{
  "media_root": "/home/user/ttd",
  "engine": "auto",
  "quality": "best",
  "include_stories": true,
  "host": "127.0.0.1",
  "port": 8787,
  "use_archive": true,
  "ask_destination": true,
  "storages": {
    "nas": "/mnt/nas/ttd",
    "cloud": "/home/user/Nextcloud/ttd"
  }
}
```

Внутри библиотеки есть два служебных каталога:

- `~/ttd/.ttd-cache/` — архивы загрузок (`gallery-dl.archive`,
  `yt-dlp.archive`), по ним пропускаются повторы.

## Разработка

```bash
make build      # сборка ./ttd
make test       # go test ./...
make vet        # go vet ./...
make fmt        # gofmt

# без make:
go build -o ttd ./cmd/ttd
go test ./...
```

Тесты работают полностью офлайн: сеть не нужна, для проверок используется
движок `mock` и временные каталоги.

Кросс-сборка под все три платформы:

```bash
GOOS=windows GOARCH=amd64 go build -o ttd.exe ./cmd/ttd
GOOS=darwin  GOARCH=arm64 go build -o ttd-macos ./cmd/ttd
GOOS=linux   GOARCH=amd64 go build -o ttd ./cmd/ttd
```

Демонстрация без обращения к TikTok (движок `mock` создаёт заглушки):

```bash
ttd --engine mock --dir /tmp/demo "https://www.tiktok.com/@user/video/123"
ttd list --dir /tmp/demo --files
TTD_ENGINE=mock ttd tui
```

Подробности архитектуры — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Частые вопросы

**TikTok отвечает `403` или «Unable to download webpage».**
Передайте cookies из браузера: `ttd --cookies-from-browser firefox <ссылка>`.

**Истории не скачиваются.**
Добавьте `--stories` или укажите прямую ссылку `…/@user/stories`.

**Файлы уже есть, а загрузка всё равно идёт заново.**
Проверьте, что не задан `--no-archive`, и что каталоги `.ttd-cache` не удалены.

**Нужно перекачать то же видео снова.**
Запустите с `--no-archive` — тогда повторы не пропускаются.

**Хочу другой каталог библиотеки.**
`ttd --dir /путь <ссылка>`, `ttd config --set-dir /путь` или задайте
`media_root` в настройках.

**Как сохранять на NAS или в Nextcloud?**
Смонтируйте сетевую папку (SMB/NFS/sshfs) или папку синхронизации и добавьте
профиль: `ttd config --add-storage nas=/mnt/nas/ttd`, затем
`ttd --to nas <ссылка>`. Подробности — в разделе
[Куда сохранять](#куда-сохранять-локально-nas-и-облако).

**Нужна разовая папка без библиотеки.**
`ttd --temp /путь <ссылка>`: файлы без папок-дат, без архива и без индекса.
Или выберите «разовая папка» в вопросе после загрузки.

**Windows: почему папки называются `19.10.2026 - 17.10.2026`?**
Символ `|` запрещён в именах файлов Windows. `ttd` читает обе формы, поэтому
библиотеку можно переносить между системами.

**Windows: `ttd` не находится после установки.**
Откройте новый терминал: установщик добавляет каталог в PATH пользователя, но
уже запущенные окна его не видят. Проверьте: `ttd doctor` (в PowerShell).

**Нужен ли интернет для установки?**
Нет. Движки и их зависимости уже встроены в бинарник и ставятся через
`pip --no-index`. Интернет нужен только для скачивания самих видео и для
необязательного обновления движков `ttd install --online`.

**TikTok перестал скачиваться после обновления сайта.**
Обновите движки, когда есть интернет: `ttd install --online`. Если интернета
нет, скачайте новые колёса на другой машине и выполните
`ttd install --wheels <каталог>`.

**Работает ли без Python?**
Go-бинарник — да, но движки gallery-dl и yt-dlp написаны на Python, поэтому для
загрузок нужен **Python 3.10+**. `ttd install` создаёт изолированное окружение
в `~/.local/share/ttd/venv`, системный Python при этом не засоряется.
