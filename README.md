# ttd — загрузчик видео и фото из TikTok

`ttd` скачивает видео, фото-слайдшоу, публикации профиля и истории из TikTok
и раскладывает файлы по папкам, в имени которых указаны **дата скачивания** и
**дата публикации**:

```
~/ttd/19.10.2026 | 17.10.2026/user_7412345678901234567.mp4
        └──────┬──────┘ └──────┬──────┘
        дата скачивания   дата публикации
```

Программа написана на Go (один статический бинарник, без внешних Go-зависимостей)
и умеет работать в трёх режимах:

| Режим | Команда | Для чего |
| --- | --- | --- |
| **CLI** | `ttd <ссылка>` | скрипты, автоматизация, быстрые загрузки |
| **TUI** | `ttd tui` | полноэкранный интерфейс в терминале |
| **Web** | `ttd web` | сайт на `localhost`, открывается скриптом |

## Возможности

- **Видео, фото и слайдшоу.** Обычные видео, публикации с несколькими фото и
  «карусели» скачиваются полностью.
- **Профиль целиком.** Укажите ссылку на аккаунт — скачаются все публикации.
- **Истории.** Поддерживаются истории профиля (фото и видео) — ключ `--stories`.
- **Максимальное качество.** Программа сама определяет доступные разрешения и
  выбирает наилучшее (`ttd probe` показывает, что доступно).
- **Папки с двумя датами.** Скачанные сегодня файлы старых публикаций попадают
  в разные папки — видно и когда скачали, и когда это было опубликовано.
- **Пропуск повторов.** Уже скачанное не качается заново (можно отключить).
- **Три интерфейса** — командная строка, TUI и локальный сайт.
- **Один бинарник.** Go-код не тянет внешних Go-модулей; движки ставятся
  автоматически в изолированное окружение в каталоге данных.

## Быстрый старт

Нужны **Go 1.22+** и **Python 3.9+** (Python нужен только движкам загрузки).

```bash
git clone <адрес-репозитория> ttd
cd ttd
./install.sh             # собрать, установить в PATH, поставить движки
ttd doctor               # проверка окружения
ttd "https://www.tiktok.com/@user/video/7412345678901234567"
```

Установщик кладёт программу в `~/.local/bin`, движки — в
`~/.local/share/ttd/venv`, и добавляет нужный путь в `~/.bashrc` и `~/.zshrc`.
После этого `ttd` работает из любого каталога, а исходники можно удалить.

Запуск сайта на localhost:

```bash
./scripts/serve.sh       # или:  ttd web
```

Подробная пошаговая инструкция — в файле [INSTALL.md](INSTALL.md).

### Что и куда устанавливается

| Что | Куда | Как изменить |
| --- | --- | --- |
| Бинарник `ttd` | `~/.local/bin/ttd` | `./install.sh --bin-dir …` |
| Движки `gallery-dl`, `yt-dlp` | `~/.local/share/ttd/venv` | `./install.sh --data-dir …` |
| Настройки | `~/.config/ttd/config.json` | — |
| Скачанные файлы | `~/ttd` | `--dir …` или `media_root` |

## Как работает раскладка по датам

Каждый файл кладётся в папку вида:

```
[ДАТА СКАЧИВАНИЯ] | [ДАТА ПУБЛИКАЦИЙ]
```

в формате `ДД.ММ.ГГГГ`, внутри каталога библиотеки (по умолчанию `~/ttd`).

Например, вы сегодня (19.10.2026) скачали три публикации профиля:

```
~/ttd/
├── 19.10.2026 | 19.10.2026/     ← опубликовано и скачано сегодня
│   └── user_7390000000000000001.mp4
├── 19.10.2026 | 17.10.2026/     ← скачано сегодня, опубликовано 17-го
│   └── user_7389000000000000002.mp4
└── 19.10.2026 | 01.10.2025/     ← скачано сегодня, опубликовано год назад
    ├── user_7380000000000000003_01.jpg
    └── user_7380000000000000003_02.jpg
```

Дата публикации берётся из метаданных, которые возвращает движок:

- **gallery-dl** — флаг `--write-metadata` (поле `date`);
- **yt-dlp** — флаг `--write-info-json` (поля `upload_date` / `timestamp`).

Служебные файлы метаданных после раскладки удаляются. Если движок не смог
определить дату публикации, справа подставляется дата скачивания.

Дату скачивания можно задать вручную: `ttd --date 01.01.2027 <ссылка>`.

## Использование CLI

```bash
# Скачать одно видео
ttd "https://www.tiktok.com/@user/video/7412345678901234567"

# Публикация с фото
ttd "https://www.tiktok.com/@user/photo/7412345678901234567"

# Весь профиль вместе с историями
ttd --stories "https://www.tiktok.com/@user"

# Несколько ссылок сразу
ttd URL1 URL2 URL3

# Посмотреть доступное качество, не скачивая
ttd probe "https://www.tiktok.com/@user/video/7412345678901234567"

# Список библиотеки (с файлами)
ttd list --files

# Результат в JSON (для скриптов)
ttd -j "https://www.tiktok.com/@user/video/7412345678901234567"
```

Основные флаги команды `download`:

| Флаг | Значение |
| --- | --- |
| `-d`, `--dir <путь>` | каталог библиотеки (по умолчанию `~/ttd`) |
| `-e`, `--engine <движок>` | `auto`, `gallery-dl`, `yt-dlp`, `mock` |
| `-q`, `--quality <качество>` | `best`, `1080`, `720`, `480` |
| `--date <ДД.ММ.ГГГГ>` | дата скачивания для папки |
| `--stories` / `--no-stories` | качать ли истории профиля |
| `-n`, `--limit <число>` | ограничить число записей |
| `--audio-only` | только звук (mp3) |
| `--cookies <файл>` | cookies в формате Netscape |
| `--cookies-from-browser <браузер>` | взять cookies из браузера (`firefox`, `chrome`, …) |
| `--no-archive` | не пропускать уже скачанное |
| `--engine-arg <аргумент>` | дополнительный аргумент движка (можно повторять) |
| `--dry-run`, `--plan` | показать план без скачивания |
| `-j`, `--json` | машинночитаемый результат |
| `-v`, `--verbose` | подробный журнал |
| `-Q`, `--quiet` | без промежуточного вывода |

Остальные команды:

```bash
ttd install     # установить/переустановить движки
ttd doctor      # состояние окружения и версии движков
ttd config      # показать текущие настройки
ttd version     # версия
ttd help        # справка
```

Коды выхода: `0` — успех, `1` — были ошибки, `2` — неверные аргументы,
`130` — прервано пользователем (Ctrl-C).

## Текстовый интерфейс (TUI)

```bash
ttd tui
```

Управление:

| Клавиша | Действие |
| --- | --- |
| `Enter` | добавить ссылку в очередь |
| `F5` / `Ctrl-D` | начать загрузку |
| `F10` / `Ctrl-Q` | выход |
| `Tab` | включить/выключить истории |
| `Ctrl-L` | очистить очередь |

Экран показывает очередь с состоянием каждой ссылки, прогресс, текущий файл и
журнал событий. Если терминал не поддерживает полноэкранный режим, TUI
автоматически переключается на построчный ввод.

## Локальный сайт (Web)

```bash
ttd web                       # по умолчанию http://127.0.0.1:8787/
ttd web --port 9000           # другой порт
ttd web --host 0.0.0.0        # слушать все интерфейсы
ttd web --no-browser          # не открывать браузер автоматически

./scripts/serve.sh            # то же самое через скрипт
```

На странице можно:

- вставить список ссылок и скачать их;
- выбрать движок, качество, включить истории и «только звук»;
- видеть прогресс, журнал и кнопку остановки;
- просматривать библиотеку: папки-даты, превью фото и проигрывание видео прямо
  в браузере (сервер поддерживает HTTP `Range`, поэтому перемотка работает).

Веб-API (на случай интеграций):

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/meta` | настройки, пути, версии движков |
| `GET` | `/api/library` | список папок-дат и файлов |
| `GET` | `/api/files?folder=…&name=…` | отдача файла (с поддержкой `Range`) |
| `POST` | `/api/download` | запустить загрузку, вернуть `id` задачи |
| `GET` | `/api/job/<id>?since=N` | состояние задачи и события начиная с `N` |
| `POST` | `/api/job/<id>/cancel` | остановить задачу |
| `POST` | `/api/install` | установить движки |

## Поддерживаемые ссылки

| Тип ссылки | Пример | Как обрабатывается |
| --- | --- | --- |
| Видео | `tiktok.com/@user/video/7412…` | yt-dlp (максимальное качество), gallery-dl как запасной |
| Фото / слайдшоу | `tiktok.com/@user/photo/7412…` | gallery-dl (все кадры публикации) |
| Профиль | `tiktok.com/@user` | gallery-dl — все публикации |
| Истории | `tiktok.com/@user/stories` | gallery-dl (нужен флаг `--stories` или ссылка на истории) |
| Подборка | `tiktok.com/collection/…`, `tiktok.com/music/…` | gallery-dl |
| Короткие ссылки | `vm.tiktok.com/…` | разрешаются автоматически |

Движки — это внешние программы, которые `ttd install` ставит в изолированное
окружение `~/.local/share/ttd/venv`:

- **[gallery-dl](https://github.com/mikf/gallery-dl)** — основной движок:
  понимает профили, фото-слайдшоу и **истории**, умеет сортировать видео по
  убыванию разрешения;
- **[yt-dlp](https://github.com/yt-dlp/yt-dlp)** — скачивает одиночные видео с
  явным выбором наилучшего качества и работает как запасной вариант.

Оба вызываются как подпроцессы, поэтому Go-код остаётся без зависимостей.

## Качество загрузки

Для одиночного видео выбирается максимально возможное качество:

```
-f "bestvideo*+bestaudio/best" --merge-output-format mp4
```

Итоговый файл — `mp4` со склеенными дорожками. Формат `bestvideo*` заставляет
yt-dlp брать видео даже в тех случаях, когда оно помечено как «только с
аудио» — так на TikTok получается максимальное разрешение.

Проверить доступные разрешения заранее:

```bash
ttd probe "https://www.tiktok.com/@user/video/7412345678901234567"
```

Ограничить разрешение можно флагом `-q`: `-q 720` даст не выше 720p,
`-q 1080` — не выше 1080p.

## Доступ по cookies

Иногда TikTok отвечает `403` или просит вход. Тогда передайте cookies:

```bash
# взять из браузера (самый простой способ)
ttd --cookies-from-browser firefox "https://www.tiktok.com/@user/video/7412…"

# или указать файл cookies в формате Netscape
ttd --cookies ~/cookies.txt "https://www.tiktok.com/@user/video/7412…"
```

Поддерживаются браузеры, которые понимает движок: `firefox`, `chrome`,
`chromium`, `edge`, `brave`, `opera`, `safari`, `vivaldi`, `whale`.

## Настройки

Файл настроек: `~/.config/ttd/config.json` (создаётся при необходимости).
Посмотреть действующие значения — `ttd config`.

| Поле | Переменная окружения | По умолчанию | Описание |
| --- | --- | --- | --- |
| `media_root` | `TTD_DIR` | `~/ttd` | каталог библиотеки |
| `engine` | `TTD_ENGINE` | `auto` | движок по умолчанию |
| `quality` | `TTD_QUALITY` | `best` | качество по умолчанию |
| `include_stories` | `TTD_STORIES` | `false` | качать истории профиля |
| `cookies` | `TTD_COOKIES` | — | путь к файлу cookies |
| `cookies_from_browser` | `TTD_COOKIES_FROM_BROWSER` | — | браузер для cookies |
| `host` | `TTD_HOST` | `127.0.0.1` | адрес веб-сервера |
| `port` | `TTD_PORT` | `8787` | порт веб-сервера |
| `download_limit` | `TTD_LIMIT` | `0` (без лимита) | ограничение числа записей |
| `gallery_dl` | `TTD_GALLERY_DL` | — | путь к gallery-dl |
| `yt_dlp` | `TTD_YT_DLP` | — | путь к yt-dlp |
| `use_archive` | `TTD_ARCHIVE` | `true` | пропускать уже скачанное |

Дополнительные переменные (не входят в файл настроек):

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `TTD_HOME` | каталог бинарника | где искать исходники и `.venv` |
| `TTD_DATA_DIR` | `~/.local/share/ttd` | каталог данных установленного ttd |
| `TTD_VENV` | — | явный путь к окружению с движками |

Так `ttd` ищет окружение с движками: `TTD_VENV` → `.venv` рядом с исходниками
→ `<каталог данных>/venv` → системные каталоги. Если готового окружения нет,
новое создаётся в `TTD_DATA_DIR` (по умолчанию `~/.local/share/ttd`).

Пример `~/.config/ttd/config.json`:

```json
{
  "media_root": "/home/user/ttd",
  "engine": "auto",
  "quality": "best",
  "include_stories": true,
  "host": "127.0.0.1",
  "port": 8787,
  "use_archive": true
}
```

## Структура проекта

```
ttd/
├── cmd/ttd/main.go            точка входа
├── internal/
│   ├── cli/                   разбор аргументов, команды, вывод
│   ├── config/                настройки, пути, переменные окружения
│   ├── engines/               gallery-dl и yt-dlp, классификация ссылок, зондирование
│   ├── installer/             установка движков, диагностика
│   ├── library/               папки-даты, перечисление файлов
│   ├── model/                 общие структуры данных
│   ├── service/               оркестрация: staging → раскладка по датам
│   ├── tui/                   полноэкранный интерфейс (raw-режим терминала)
│   ├── util/                  даты, размеры, запуск процессов
│   ├── version/               версия
│   └── web/                   HTTP-сервер и страница (index.html)
├── install.sh                 установщик (сборка, PATH, движки)
├── scripts/install.sh         совместимый вызов установщика
├── scripts/serve.sh           запуск сайта
├── docs/ARCHITECTURE.md       как всё устроено внутри
├── README.md
└── INSTALL.md
```

Внутри библиотеки есть два служебных каталога:

- `~/ttd/.staging/` — временный: сюда движок пишет файлы, а `ttd` затем
  переносит их в папки-даты;
- `~/ttd/.ttd-cache/` — архивы загрузок (`gallery-dl.archive`,
  `yt-dlp.archive`), по ним пропускаются повторы.

## Разработка

```bash
make build      # сборка ./ttd
make test       # go test ./...
make vet        # go vet ./...
make fmt        # gofmt

# без make:
go build -o ttd ./cmd/ttd
go test ./...
```

Тесты работают полностью офлайн: сеть не нужна, для проверок используется
движок `mock` и временные каталоги.

Демонстрация без обращения к TikTok (движок `mock` создаёт заглушки):

```bash
ttd --engine mock --dir /tmp/demo "https://www.tiktok.com/@user/video/123"
ttd list --dir /tmp/demo --files
TTD_ENGINE=mock ttd tui
```

Подробности архитектуры — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Частые вопросы

**TikTok отвечает `403` или «Unable to download webpage».**
Передайте cookies из браузера: `ttd --cookies-from-browser firefox <ссылка>`.

**Истории не скачиваются.**
Добавьте `--stories` или укажите прямую ссылку `…/@user/stories`.

**Файлы уже есть, а загрузка всё равно идёт заново.**
Проверьте, что не задан `--no-archive`, и что каталоги `.ttd-cache` не удалены.

**Нужно перекачать то же видео снова.**
Запустите с `--no-archive` — тогда повторы не пропускаются.

**Хочу другой каталог библиотеки.**
`ttd --dir /путь <ссылка>` или задайте `media_root` в настройках.

**Работает ли без Python?**
Go-бинарник — да, но движки gallery-dl и yt-dlp написаны на Python, поэтому для
загрузок Python нужен. `./install.sh` создаёт изолированное окружение в
`~/.local/share/ttd/venv`, системный Python при этом не засоряется.
